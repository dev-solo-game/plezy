# 媒体 ID 说明与作品状态同步方案

更新日期为 2026-11-12。本版按已确认的同步需求精简。

本文说明当前代码中的 ID，以及片头片尾、观看进度和多端同步使用的保存方式。2026-11-12 已完成本机已刮削作品观看状态的独立存储和本版新记录的重扫恢复。片头片尾功能与跨端传输留待后续实现。

## 1. 已确定的范围

未来账号同步两类数据。

| 数据 | 内容 |
| --- | --- |
| 添加的媒体来源 | 夸克、SMB、WebDAV 等挂载，以及 Emby、Jellyfin 服务器连接的来源描述。 |
| 来源中的作品状态 | 电影或整剧的外部 ID、观看进度、已看状态、片头片尾设置，以及电视剧各集的观看状态。 |

**只有已经刮削入库且取得明确作品 ID 的电影或整剧，才保存和同步上述作品配置。** 未刮削条目按普通文件浏览和播放，本功能的配置入口提示先完成刮削。这里没有待刮削配置、临时规则或后续升级临时键的流程。

本地媒体库以本机刮削结果确认作品。Emby、Jellyfin 使用服务器已有元数据，满足电影或整剧身份及外部 ID 要求即可接入。

各端独立扫描和建立媒体索引，下载文件和访问凭据在设备上管理。媒体源描述同步到新设备后，按该设备的授权和实际路径完成连接。账号内的资料隔离沿用账号同步工作区设计。

## 2. 当前各种 ID 的含义

| ID 或字段 | 含义 | 当前用途与注意事项 |
| --- | --- | --- |
| LibraryItems.id | 本地电影、剧、季、集记录的自增 ID | 当前设备内定位条目。不同设备独立建库时通常不同。 |
| MediaItem.id | 统一媒体模型的条目 ID | 本地库来自本地记录，Emby/Jellyfin 来自服务器条目。 |
| parentId | 当前条目的直接父级 | 本地季指向整剧，集指向季。 |
| 本地 showId | 季或集所属的整剧记录 | 用于查找整部剧和该剧下的集。 |
| grandparentId | 统一模型中的上层条目 ID | 对剧集通常指整剧。本地集由 showId 映射，Emby/Jellyfin 集通常来自 SeriesId。 |
| serverId | 当前媒体客户端的服务器身份 | 本地库固定为 local-library，Emby/Jellyfin 使用服务器 machine ID。 |
| globalKey | 当前条目的完整键 | 通常为 serverId:itemId。 |
| seriesGlobalKey | 当前季或集所属整剧的完整键 | 通常为 serverId:showItemId。整剧和电影自身返回空。 |
| libraryId / libraryGlobalKey | 当前来源内的媒体库或分类库身份 | 用于展示、过滤、库级设置。libraryGlobalKey 通常为 serverId:libraryId。 |
| mountId | 一条挂载记录的 UUID | 表示一个夸克、SMB 等挂载。当前创建时生成，编辑时沿用。 |
| LibraryFiles.id | 本地索引中的文件 ID | 选择具体文件、保存文件信息。 |
| remoteId | 驱动返回的远端文件 ID | 需结合挂载或账号使用，稳定性取决于存储服务。 |
| mountId + path | 挂载内的相对路径 | 文件表的唯一索引。重命名或移动文件可能改变路径。 |
| mediaSourceId | 当前条目的具体播放版本 ID | 本地库目前映射为文件 ID 的字符串，服务器媒体使用服务器返回值。 |
| connectionId | 一份保存的服务器连接记录 ID | 表示登录连接，本机可有指向同一服务器的不同连接记录。 |
| serverMachineId | Emby/Jellyfin 报告的服务器身份 | 同一服务器通过不同地址接入时可用于关联。 |
| userId / profileId | 服务器用户或应用档案 | 控制用户身份及数据归属，需要所在账号或工作区的作用域。 |
| deviceId | 设备身份 | 标识操作和播放发生在哪台设备。 |
| clientScopeId | 某些客户端或缓存请求的作用域 | 下载等记录中可用于找回获取元数据时的客户端环境，具体归属由对应业务决定。 |
| TMDB、IMDb 等 ID | 元数据服务中的作品身份 | 跨端匹配作品时使用，需要带媒体类型和提供方。 |

这些 ID 已在代码中存在。跨端使用时，不能仅凭相同的本机数字认定是同一作品。

## 3. globalKey 和 seriesGlobalKey 的区别

假设本地库里整剧 A 的 ID 是 42，第 1 季是 60，第 1 集和第 2 集分别是 105、106。

| 当前条目 | globalKey | seriesGlobalKey |
| --- | --- | --- |
| 整剧 A | local-library:42 | 空，整剧使用自己的 globalKey |
| 第 1 季 | local-library:60 | local-library:42 |
| 第 1 集 | local-library:105 | local-library:42 |
| 第 2 集 | local-library:106 | local-library:42 |
| 电影 B，ID 为 80 | local-library:80 | 空，电影使用自己的 globalKey |

`globalKey` 定位当前正在查看或播放的条目。`seriesGlobalKey` 从一季或一集定位到整部剧，所以适合读取整剧共享的片头片尾设置。

当前 getter 在缺少 serverId 时会退回裸条目 ID。新作品状态只有在来源和作品身份都明确时才保存。

A 设备的整剧 globalKey 可能是 `local-library:42`，B 设备是 `local-library:817`。同步时使用稳定来源和作品外部 ID，各端再映射到自己的条目。

代码依据见 [键生成](/E:/Code/plezy/lib/utils/global_key_utils.dart)、[媒体键定义](/E:/Code/plezy/lib/media/media_item.dart:312)。

## 4. 来源、作品和文件的关系

```text
默认本地媒体库
  已刮削的剧 A
    第 1 集
      夸克文件，挂载 Q
      SMB 文件，挂载 S
    第 2 集
      夸克文件，挂载 Q
```

本地同一条目下的不同文件是可选播放版本。按照此前确定的行为，同一本地作品的夸克、SMB 版本共用整剧配置及该集观看状态。

媒体源同步记录和作品状态的来源范围对应如下。

| 对象 | 采用的身份 |
| --- | --- |
| 一条夸克、SMB 或 WebDAV 挂载描述 | 复用 mountId 作为该来源记录 ID，同步到其他设备时保留。 |
| 一台 Emby/Jellyfin 服务器 | 使用后端类型和服务器 machine ID 确认来源，连接记录包含设备所需的连接描述。 |
| 默认本地库中的作品状态 | 当前账号内固定使用 local-library 作为 sourceKey。 |
| Emby/Jellyfin 中的作品状态 | 使用带后端类型的服务器身份作为 sourceKey，例如 emby/server-A。 |

本版按一个账号拥有一个默认本地媒体库规划。账号工作区已经提供隔离范围，所以可以使用固定的 `local-library`。两台设备在同一账号下扫描到相同作品时，即使各自存在不同挂载，也会匹配到该账号默认本地库中的同一作品状态。

这与本地多版本共用设置相符。本地库与 Emby/Jellyfin 之间，以及不同服务器之间，sourceKey 不同，各自维护状态。未来如明确需要同账号内多个互相隔离的本地库，再为这些库增加不同 sourceKey。

各端独立添加的挂载会生成不同 UUID。通过同步恢复的挂载沿用原 ID。已存在的重复挂载可在导入时确认是否关联，避免仅按显示名称自动合并。

## 5. 作品状态的保存键

在当前账号或工作区内，采用以下结构定位一部作品。

```text
sourceKey + mediaType + provider + externalId
```

| 字段 | 取值及含义 |
| --- | --- |
| sourceKey | 默认本地库，或某一台 Emby/Jellyfin 服务器。 |
| mediaType | movie 或 show，展示分类中的动漫、综艺根据作品实际类型归入其中。 |
| provider | tmdb 或 imdb。 |
| externalId | 电影或整部剧在对应元数据服务中的 ID。 |

继续沿用此前确定的 TMDB 优先规则，缺少 TMDB 且已明确匹配到 IMDb 时使用 IMDb。记录可以同时保留已知的 TMDB、IMDb 字段，供查询时核对同一作品。两端分别只有 TMDB 和 IMDb 时，需要补齐同作品的元数据关联后才能匹配。

电视剧使用整剧的外部 ID。季号和集号用于其下面每集的观看状态。未获得整剧身份或季集编号的条目，完成元数据匹配后再参与同步。

示例键如下，编号均为说明用途。

| 作品位置 | 匹配身份 |
| --- | --- |
| 本地剧 A | local-library / show / tmdb / 12345 |
| 本地电影 B | local-library / movie / imdb / tt0000001 |
| Emby A 中的剧 A | emby/server-A / show / tmdb / 12345 |
| Jellyfin B 中的剧 A | jellyfin/server-B / show / tmdb / 12345 |

直接按这组身份读取和更新作品状态即可。规则内容跟随作品状态保存。当前代码已有外部 ID 查找能力，接入时补上 sourceKey 的路由和明确的匹配结果检查。

代码依据见 [外部 ID 查询](/E:/Code/plezy/lib/library/library_repository.dart:263)、[本地客户端反查](/E:/Code/plezy/lib/library/local_library_client.dart:1357)。

## 6. 具体保存哪些内容

| 对象 | 保存内容 | 归属层级 |
| --- | --- | --- |
| 电影观看状态 | positionMs、durationMs、watched、updatedAt | 来源内的一部电影 |
| 电视剧观看状态 | 每一集的 seasonNumber、episodeNumber、positionMs、durationMs、watched、updatedAt | 来源内一部剧的具体一集 |
| 片头设置 | enabled、startMs、endMs | 来源内的一部电影或整部剧 |
| 片尾设置 | enabled、durationFromEndMs，可选彩蛋跳转位置 | 来源内的一部电影或整部剧 |
| 看了几集 | 从该剧已看状态为 true 的不同集统计 | 整剧汇总 |
| 最近看到哪集 | 根据各集的最后观看信息确定 | 整剧汇总 |

“看了几集”由逐集状态计算。例如第 1、2、5 集已看，结果为 3 集，避免只保存“看到第 5 集”而误认为前 5 集都已看。重看同一集也只计一次已看集数，标记未看后相应减少。

片头片尾从任意一集修改都保存到整剧。每集仍然保留自己的观看进度。特别篇可以使用季号 0，存在不同编排时，须在季集映射一致后应用单集状态。

电影有自己的时长和位置；单集也保存上次播放时长。切换到不同剪辑后，根据当前实际时长检查进度和跳过区间。相同作品 ID 无法保证文件的时间轴相同，首版按作品和单集共用，差异由用户调整。

“跳过片尾延迟”继续作为设备上的全局播放设置保存，默认 5 秒。逐作品数据只记录该作品的区间。有下一集且片尾区间延伸到视频结束时，使用「播放下一集倒计时」。

建议的剧集状态示例为以下形态。实际数据库可使用作品表和逐集状态表，示例 JSON 用于表达数据关系。

```json
{
  "sourceKey": "local-library",
  "mediaType": "show",
  "provider": "tmdb",
  "externalId": "12345",
  "externalIds": {"tmdb": "12345", "imdb": "tt0000001"},
  "skip": {
    "intro": {"enabled": true, "startMs": 40000, "endMs": 130000},
    "credits": {"enabled": true, "durationFromEndMs": 90000}
  },
  "episodes": [
    {"seasonNumber": 1, "episodeNumber": 1, "positionMs": 2700000, "durationMs": 2700000, "watched": true},
    {"seasonNumber": 1, "episodeNumber": 2, "positionMs": 600000, "durationMs": 2700000, "watched": false}
  ]
}
```

## 7. 保存、读取和同步如何工作

| 场景 | 流程 |
| --- | --- |
| 电影详情设置跳过 | 读取来源和电影外部 ID，保存该作品的跳过字段。 |
| 第 3 集设置跳过 | 通过父级关系找到整剧，读取整剧外部 ID，保存整剧跳过字段。 |
| 第 3 集看到 10 分钟 | 按整剧身份及季集编号保存该集位置。 |
| B 设备接收作品状态 | 保存来源、作品身份及状态，随后根据本机索引找到相应电影或整剧。 |
| B 设备尚未扫描到该作品 | 保留收到的已识别作品状态，等本机入库后再读取。 |
| 本机未刮削的文件 | 完成刮削入库和作品匹配后，才创建或读取对应作品配置。 |
| 清索引后重新扫描 | 保留用户作品状态，刮削得到相同来源和外部 ID 后重新读取。 |

收到 A 设备已经刮削的作品状态后，B 尚未入库也可以保留该同步记录。这与为未刮削文件创建配置是两种不同的情况。

通过外部 ID 查询得到整剧后，可以读取它的 globalKey。该剧各集的 seriesGlobalKey 指向这个整剧键。定位某一集时，再通过季号、集号查询当前端对应条目。

当前本地查询只取首个匹配结果。新读取流程需要检查重复候选，明确属于同一作品后再使用。服务器条目的获取还取决于当前连接的访问权限和可用元数据。

## 8. 只处理必要的数据边界

| 情况 | 处理规则 |
| --- | --- |
| 显示名称、服务器 URL 或登录凭据改变 | 仍按原挂载 ID 或服务器身份管理来源，作品状态继续按 sourceKey 查找。 |
| 清理扫描索引 | 用户作品状态独立保存，重扫后按外部 ID 找回。 |
| 重复条目合并 | 相同作品身份读取同一份状态，刷新当前端的条目关联。 |
| 错误刮削修正为另一作品 | 改用修正后作品的身份读取。原作品的状态保留在原作品名下。 |
| 同作品补齐另一种外部 ID | 有明确元数据对应关系时关联已有状态；冲突时保留双方，避免覆盖。 |
| 修改跳过设置，同时另一端更新观看进度 | 按字段组分别提交，跳过设置和逐集进度互不覆盖。 |
| 两端修改同一集进度 | 后续同步使用现有版本校验方案，冲突保留待处理值；单纯取最大进度会破坏重播和回看语义。 |
| 清除跳过或标记未看 | 作为明确修改保存和同步，区分尚未收到数据与用户主动清除。 |
| 删除媒体来源 | 以删除来源操作处理，作品状态的清除由明确的数据清理操作决定。 |

时间戳用于最后观看时间和展示。网络重试、版本冲突沿用账号同步设计的通用机制，在接入传输时处理。

## 11. 文档状态与决定

本版采用账号内一个默认本地媒体库的范围，直接使用固定 sourceKey，并复用挂载和服务器已有 ID。上一版新增逻辑库 UUID、单独规则 UUID、临时未刮削配置及通用身份绑定体系的设计已由本版替换。

TMDB 优先、IMDb 回退沿用此前讨论。其提供方字段明确保存在数据中。未来如需要仅使用 IMDb，可再统一元数据要求；本版以已经获得的明确作品身份实现需求。

本机数据保存阶段已经实现。数据库版本为 32，新增 WorkWatchStates 和 LibraryWorkBindings。本版从空作品状态开始，重新刮削入库后的播放操作生成新记录。打开数据库时从本版 WorkWatchStates 恢复当前索引投影。旧 itemId 观看记录的自动导入已移除。

LibraryUserStates 作为首页、详情及播放入口使用的当前索引投影，写入时和作品状态在同一事务内更新。删除媒体条目只删除投影和绑定，作品观看状态保留。修正为另一个作品时，当前条目改读新作品状态，原作品状态继续保留。

同一本地作品的多文件版本及重复索引条目共享状态。IMDb 匹配补充 TMDB 时，只有明确保持同一 IMDb 作品才承接原状态。Emby/Jellyfin 现有观看状态继续由对应服务器读写，本次验证了独立存储结构中的来源隔离；实际账号同步尚未接入。

## 12. 手动片头片尾实现与验收（2026-11-12）

本阶段复用当前工作区的 LibrarySettings 保存作品设置，不新增账号同步、冲突处理或旧设置转换。键为 `work-skip:` 加 WorkIdentity.stateKey（季号、集号均为 -1）；值为 WorkSkipSettings JSON。它与扫描条目、物理文件及逐集观看状态分开保存，删除索引重新刮削后按相同作品身份读取。

| 范围 | 当前行为 |
| --- | --- |
| 本地电影 / 整剧 | source 固定 local-library，TMDB 优先，IMDb 回退。挂载、路径、文件版本不参与设置键。 |
| Emby / Jellyfin | source 为后端类型与服务器身份的组合。剧集先解析整剧，再取外部 ID；已解析的身份缓存支持离线读取。不同服务器与本地库互不合并。 |
| 未刮削或没有 TMDB/IMDb | 提示先匹配作品，不创建跳过配置。 |
| 整剧已匹配但季集号暂缺 | 可以使用整剧跳过规则；逐集观看状态仍要求季号、集号完整。 |
| 观看状态 | 编辑跳过规则不修改进度、已看或收藏。 |

| 入口 / 操作 | 行为 |
| --- | --- |
| 媒体详情菜单 | “跳过片头片尾”，电影、剧、季、集进入同一窗口。 |
| 播放器播放设置 | “跳过片头片尾”，打开时暂停，保存或取消后恢复打开前的播放状态。原本暂停则继续暂停。 |
| PC 进度条右键 | 左半按点击时间预填片头结束；中点及右半按总时长减点击时间预填片尾时长。右键不会定位播放。另一个区间保留，取消不写入。 |
| 片头 | 可启用、关闭，设置开始/结束时间。自然播放进入区间直接跳过；开始时间支持保留冷开场。 |
| 片尾 | 按距离视频末尾的时长定义。有下一集且跳过会结束本集时，自然进入片尾就显示「下一集」窗口，本集继续播放。窗口按「播放下一集倒计时」计时，取消后可看完片尾。其余跳过场景使用「跳过片尾延迟」，默认 5 秒，允许 0～30 秒。 |
| 彩蛋 | “保留结尾彩蛋”填写跳转后剩余时长；00:00 表示结束。非零值只定位、不触发播放完成，包括保留 1 秒。 |
| 取消本次跳过 | 点击取消按钮或遥控返回，取消本次区间访问的自动跳过，不修改作品规则。 |
| 手动回看 | 手动定位进入片头/片尾时不再自动跳走，仍可手动点跳过；异步定位期间的旧位置事件不会重启自动跳过。 |
| 进度条 | 蓝色竖条标记片头结束位置，金色竖条标记片尾开始位置，两条标记均在进度条高度内。 |
| 文件时长变化 | 根据实际时长重建区间；越界、重叠或没有有效时长时不自动跳过，原配置保留供用户修改。 |
| 播放完成 | 跳过至结尾进入现有完成流程，处理最终进度、已看、继续观看、自动连播和睡眠定时器。不会绕过偏好直接调用下一集。 |

旧的全局片头/片尾 Off/Button/Auto、章节正则及强制章节回退入口已移除。播放器只执行手动作品规则；章节列表与正常章节导航保留。原 `auto_skip_delay` 数值键继续用于“跳过片尾延迟时间”，默认 5 秒，不再延迟片头。
