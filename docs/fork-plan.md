# 二次開發計劃：無伺服器的本地媒體庫播放器

> 狀態：階段 1 的程式碼已完成——驅動介面、本地、SMB、WebDAV、Quark、串流代理、掛載頁面；尚待在真實服務上驗證。
> 日期：2026-11-09
> 基線：plezy 2.26.0（commit `77f11b86f`）

## 1. 目標

把 plezy 從「Plex / Jellyfin / Emby 客戶端」改造成不依賴任何媒體伺服器的本地播放器：
app 自己掛載存儲、掃描、刮削、建庫、播放、下載。

- 移除所有 Plex、Jellyfin、Emby 及相關伺服器的連線能力。
- 存儲來源改為掛載：本地路徑、SMB、網盤（首版為 Quark）。
- 媒體庫改為本地掃描、刮削、入庫，每個平台都能獨立完成，不需要另一台機器。

### 預設決定（未逐項確認，可隨時推翻）

- **隨舊後端一起刪除的功能**：Live TV 與 DVR、Seerr 求片、伺服器轉碼、一起看（Watch Together）、
  手機遙控（Companion Remote）、Trakt / MyAnimeList / AniList / Simkl 追蹤器、Plex Discover、
  官方崩潰上報、內購、官方 OAuth 代理與日誌上傳。
- **刮削優先順序**：
  1. 目錄內有 NFO 就用 NFO 和本地圖片，不聯網。
  2. 否則以 TMDB 為主資料。
  3. 判斷為動漫的先查 Bangumi，查不到再回退 TMDB。
  4. 豆瓣只補充中文簡介和評分，可在設定裡關閉。
- **掛載目錄的類型設定**（已確認）：每個掛載目錄在添加時選擇一種模式，之後可修改。
  - 指定類型（電影 / 電視劇 / 動漫）：整個目錄按該類型解析和刮削，不做類型猜測。
    動漫為獨立類型：按字幕組命名規則解析（絕對集數、OVA、劇場版），優先用 Bangumi 刮削，
    查不到再回退 TMDB。
  - 自動分類：按下面的規則逐個判斷。
  - 修改模式後，該目錄下未被手動鎖定的條目重新分類和刮削。
- **自動分類規則**（僅用於「自動分類」模式）：
  - 帶季集編號（`S01E02`、`第 x 集`、`EP03`）或位於季目錄下 → 劇集。
  - 字幕組括號命名（`[組名] 標題 - 01 [1080p]`）→ 動漫。
  - 其餘影片 → 電影。
- **Quark 登入**：掃碼為主，手動貼 Cookie 為備用（Android TV 也能登入）。
- **Quark 掃描頻率**：列目錄請求必須限速（請求間隔、併發數、每日上限可設定），
  定時掃描的最小間隔要比其他驅動長，並優先用增量方式減少請求數。
- **TMDB 連線**：設定裡提供自訂 API 域名、代理、自備 API key。
- **掃描觸發**：手動、啟動時、定時，可按掛載點單獨設定。

## 3. 現狀

- `lib/` 約 1000 個 Dart 檔、25 萬行；`test/` 707 個測試檔。
- 約 400 個檔案提到 Plex / Jellyfin，其中 110 個提到 Emby。
- 後端抽象已存在：`lib/media/media_server_client.dart` 定義約 100 個方法的 `MediaServerClient`，
  能力旗標在 `lib/media/server_capabilities.dart`。UI 大多只依賴這層抽象；
  直接按後端分支的非後端檔案只有 30 多個。
- 播放器：Windows、Linux、Apple 用 mpv；Android 另有 ExoPlayer。
  mpv 已支援按檔案注入 HTTP 標頭（`lib/mpv/player/player_native.dart`）。
- 資料庫：drift，schema v25（`lib/database/tables.dart`），只有 API 快取、下載、連線、profile，
  沒有媒體庫表。
- 授權：GPL-3.0。`TRADEMARKS.md` 對公開發佈的 fork 有改名要求；自用不受影響。

## 4. 架構

```
┌──────────────── 現有 UI（首頁 / 媒體庫 / 詳情 / 播放器 / 下載）────────────────┐
│                         只依賴 MediaServerClient                             │
└───────────────────────────────┬──────────────────────────────────────────────┘
                                │
                     LocalLibraryClient（新）
                                │
        ┌───────────────────────┼───────────────────────┐
        │                       │                       │
   媒體庫資料庫            掃描器 / 刮削器          串流代理（127.0.0.1）
   （drift 新表）               │                       │
                                └───────────┬───────────┘
                                            │
                                    存儲驅動層（VFS）
                             ┌──────────────┼──────────────┐
                        本地      SMB      WebDAV      Quark
```

核心思路：把本地媒體庫寫成一個新的 `MediaServerClient` 實作，資料來自本地資料庫。
先加後刪——新後端跑通後再拆舊後端，過程中 app 一直可運行。

### 4.1 存儲驅動層

統一介面（參考 OpenList 的 driver 概念）：

| 能力 | 說明 |
| --- | --- |
| `list(path)` | 列目錄，回傳名稱、大小、修改時間、是否目錄、穩定 ID |
| `stat(path)` | 取單一檔案資訊 |
| `openRead(path, range)` | 範圍讀取，回傳位元組流 |
| `link(path)` | 可選：回傳直鏈（URL、必要標頭、過期時間） |
| 寫入類 | 首版不做（重新命名、刪除、上傳） |

- 每個掛載點一筆設定：驅動類型、顯示名稱、根路徑、憑證引用。
- 憑證（Cookie、SMB 密碼）存入現有的 `credential_vault`，設定匯出時不得明文帶出。
- **本地驅動**：桌面直接走檔案系統；Android 走 SAF（專案已有 `saf_util` / `saf_stream`）。
- **SMB 驅動**：Dart 無成熟的 SMB2/3 庫，預計以 FFI 接 libsmb2，為四個首版平台各自編譯。
  動手前先做可行性驗證（見第 7 節）。
- **WebDAV 驅動**：標準 PROPFIND 列目錄、帶 Range 的 GET 讀取，支援 Basic / Digest 認證和自簽憑證選項。
  可直接掛現有的 OpenList / AList、NAS、堅果雲等。
- **Quark 驅動**：Cookie 認證；直鏈需要 Cookie 與特定 User-Agent，會過期；要做請求限速。
  流程已由專案擁有者參照 OpenList 實測可行。

### 4.2 串流代理

app 內起一個只綁定 127.0.0.1 的 HTTP 服務，所有播放和下載都經過它：

- 支援 Range 請求。
- 為上游請求注入 Cookie / User-Agent。
- 直鏈過期時自動重新取鏈，對播放器透明。
- 把 SMB 的範圍讀取轉成 HTTP。
- URL 帶隨機 token，避免本機其他程式存取。

好處是 mpv、ExoPlayer、外部播放器、下載器都只需要認識普通 HTTP。

### 4.3 媒體庫資料庫

在 drift 中新增（表名為暫定）：

- `mounts`：掛載點設定。
- `scan_entries`：掃到的原始檔案（掛載點、路徑、大小、修改時間、驅動側 ID），用於增量掃描。
- `media_items`：電影、劇集、季、集的統一條目，含類型、標題、原始標題、年份、簡介、評分、外部 ID。
- `media_files`：條目對應的檔案版本（一對多，支撐多版本），含媒體資訊欄位。
- `subtitles`：外掛字幕與檔案的關聯。
- `people`、`item_people`、`genres`、`item_genres`。
- `collections`、`playlists` 及其成員表。
- `watch_state`：播放進度、已看、最後播放時間、收藏。
- `artwork`：海報、背景圖等的來源 URL 與本地快取路徑。
- 全文搜尋索引（FTS5），涵蓋標題、原始標題、別名。

現有的 `ApiCache`、`Connections`、`Profiles`、`ProfileConnections`、`OfflineWatchProgress`
在拆除階段移除；下載相關的表保留並改為引用新的條目 ID。

### 4.4 掃描器

- 增量遍歷：以路徑 + 大小 + 修改時間（或驅動側 ID）判斷新增、變更、刪除。
- 可中斷、可續掃，進度持久化。
- 網盤驅動按掛載點限速，避免觸發風控。
- 檔名解析：年份、季集編號、中文集數、解析度、來源、編碼、字幕組、版本標記。
- 多版本合併：同一條目下的不同檔案歸為多個版本。
- 外掛字幕、同目錄圖片、NFO 的關聯。
- 忽略規則：樣片、花絮目錄、過小的檔案、`BDMV` 目錄與 `.iso`。

### 4.5 刮削器

- 來源介面統一：搜尋、取詳情、取季集、取圖片。
- 四個實作：NFO、TMDB、Bangumi、豆瓣。
- 匹配結果記錄信心度；低於門檻進「未匹配」。
- 手動匹配：搜尋 → 選擇 → 重新刮削；手動結果鎖定，重掃時不覆蓋。
- 圖片下載到本地快取，沿用現有圖片快取服務。
- 語言偏好：簡中 / 繁中 / 原文的優先順序可設定。

### 4.6 本地後端

`LocalLibraryClient implements MediaServerClient`：

- 媒體庫、分頁、篩選、排序、搜尋、繼續觀看、首頁欄位都改為本地 SQL 查詢。
- 觀看狀態、收藏、播放列表、合集直接寫本地資料庫。
- 播放初始化回傳串流代理的 URL。
- 能力旗標：關閉 Live TV、轉碼、線上字幕搜尋、片庫事件推送等。
- 伺服器專屬的方法回傳空結果或不支援。

## 5. 階段

每個階段結束時 app 都應可建置、可運行。

### 階段 1：存儲驅動層與串流代理

- 驅動介面、掛載點設定與憑證存放。
- 本地、SMB、WebDAV、Quark 四個驅動。建議順序：本地 → WebDAV → Quark → SMB，
  先用簡單的驅動把介面和代理跑通，SMB 的原生庫風險最後處理。
- 迴環串流代理。
- 一個除錯用的檔案瀏覽頁面。

**完成標準**：在除錯頁面瀏覽四種掛載點，選一個遠端影片能直接播放並拖動進度；
Quark 直鏈過期後播放不中斷。

### 階段 2：媒體庫資料庫

- 新表與遷移（schema v26 起）。
- 查詢層：分頁、篩選、排序、搜尋。

**完成標準**：用測試資料灌庫後，各查詢的單元測試通過。

### 階段 3：掃描器與自動分類

- 增量掃描、檔名解析、分類規則、多版本合併、字幕關聯、限速。
- 建立檔名解析的測試語料（中文命名、動漫、多版本）。

**完成標準**：對一個真實掛載點掃描，結果寫入 `scan_entries` 並產生待刮削條目；
重複掃描不產生重複資料；中斷後可續掃。

### 階段 4：刮削器

- 四個來源、匹配與信心度、圖片快取。
- 「未匹配」分類與手動匹配介面。

**完成標準**：掃描後的條目自動帶上標題、簡介、海報；匹配失敗的出現在未匹配分類，
手動匹配後正確入庫。

### 階段 5：本地後端接入

- 實作 `LocalLibraryClient`。
- 掛載管理介面取代伺服器登入流程。
- 下載改為經串流代理從驅動下載。

**完成標準**：不登入任何伺服器，首頁、媒體庫、詳情頁、播放、續播、標記已看、
下載與離線播放全部可用。

### 階段 6：拆除舊後端

- 刪除 Plex / Jellyfin / Emby 的客戶端、映射、認證、發現、快取。
- 刪除 profile 系統、多伺服器管理、連線註冊。
- 刪除第 2 節列出的隨之移除的功能。
- 刪除對應的測試、i18n 字串、原生端相關程式碼。
- 音樂相關程式碼保留但不出現在介面上。

**完成標準**：全庫搜尋不到三個伺服器的客戶端程式碼；分析器無錯誤；剩餘測試全部通過。

### 階段 7：收尾

- 媒體資訊探測（解析度、編碼、HDR、音軌），懶加載並寫回 `media_files`。
- 設定與媒體庫的手動匯出匯入。
- Android TV 遙控器在新介面上的焦點導航。
- 掃描與刮削的進度顯示、錯誤提示。

## 6. 後續版本

- 音樂庫：讀內嵌標籤、封面、`.lrc`，接回現有音樂介面。
- 多設備同步：把媒體庫快照和觀看進度寫到某個掛載點，其他設備讀取合併。
- iOS / iPadOS、tvOS：沙盒書籤、背景限制、tvOS 無 WebView 與存儲可被清除的處理。
- 更多網盤驅動。
- Quark 轉碼流，作為弱設備和慢網路的降級手段。

## 7. 風險與待驗證

| 項目 | 風險 | 處理 |
| --- | --- | --- |
| SMB | 已用 `dart_smb2`（基於 libsmb2）接入，Windows 可建置；尚未連過真實共享，Android、macOS、Linux 建置未驗證；不支援自訂連接埠 | 用真實 NAS 驗證播放與拖動；不行再試 `smb_connect` |
| Quark | 非官方 API，介面可能變動；掃描目錄過於頻繁會觸發風控 | 流程已實測可行；驅動內集中處理限速與重試，掃描頻率可設定且預設保守 |
| 自動分類 | 電影劇集混放的目錄在「自動分類」模式下容易誤判 | 掛載時可直接指定類型；手動匹配結果鎖定 |
| 豆瓣 | 無公開 API，非官方介面隨時失效 | 只作補充源，可關閉，失敗不影響入庫 |
| TMDB | 部分網路環境連不上 | 自訂域名與代理 |
| 無轉碼 | 高碼率影片在弱設備或慢網路上無法降級 | 後續接 Quark 轉碼流 |
| 多設備 | 每台設備各自掃描刮削，進度不互通 | 首版提供匯出匯入；同步排到後續 |
| 大庫效能 | 網盤首次掃描和刮削耗時長 | 增量、可續掃、背景執行、先顯示已完成部分 |
| 媒體資訊 | 伺服器不再提供編碼、音軌資訊 | 懶加載探測；未探測時介面隱藏相關標記 |
| 上游修復 | 分家後無法合併上游更新 | 播放器、焦點導航等修復手動挑選移植 |
| 授權 | OpenList 為 AGPL-3.0 | 只參考思路，不複製程式碼 |
| 測試 | 大量現有測試隨舊後端刪除 | 掃描、解析、刮削、查詢層新建測試 |

### SMB 套件調查（2026-11-09，僅查閱 pub.dev，未實測）

| 套件 | 實作 | 協議 | 平台 | 狀態 |
| --- | --- | --- | --- | --- |
| `dart_smb2` 0.3.0 | 基於 libsmb2（原生庫） | SMB2/3 | macOS、Windows、Linux、iOS、Android | 活躍，兩天前剛發佈；BSD-3-Clause |
| `smb_connect` 0.0.9 | 純 Dart | SMB1、2.0、2.1，無 3.x | Android、iOS、Linux、macOS、Windows | 21 個月未更新；Apache-2.0 |

已確認：`dart_smb2` 提供任意偏移的範圍讀取（`readFileRange`），原生庫由建置鉤子下載預編譯檔並核對 SHA-256，
以動態庫形式打包（libsmb2 為 LGPL-2.1，內含 OpenSSL libcrypto）。
待驗證：Android TV、macOS、Linux 上的建置，以及真實共享上的播放。
