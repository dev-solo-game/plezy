# 二次開發計劃：無伺服器的本地媒體庫播放器

> 狀態：階段 1–4 已完成，階段 5（本地後端接入）已可啟動進入媒體庫但尚未實機驗證瀏覽與播放；階段 6（刪除伺服器程式碼）未開始。
> 日期：2026-11-09
> 基線：plezy 2.26.0（commit `77f11b86f`）

## 1. 目標

把 plezy 從「Plex / Jellyfin / Emby 客戶端」改造成不依賴任何媒體伺服器的本地播放器：
app 自己掛載存儲、掃描、刮削、建庫、播放、下載。

- 移除所有 Plex、Jellyfin、Emby 及相關伺服器的連線能力。
- 存儲來源改為掛載：本地路徑、SMB、網盤（首版為 Quark）。
- 媒體庫改為本地掃描、刮削、入庫，每個平台都能獨立完成，不需要另一台機器。

### 預設決定（未逐項確認，可隨時推翻）

- **隨舊後端一起刪除的功能**：Live TV 與 DVR、Seerr 求片、伺服器轉碼、一起看（Watch Together）、
  手機遙控（Companion Remote）、Trakt / MyAnimeList / AniList / Simkl 追蹤器、Plex Discover、
  官方崩潰上報、內購、官方 OAuth 代理與日誌上傳。
- **刮削優先順序**：
  1. 以 TMDB 為主資料。
  2. 檔名或資料夾看起來像動漫的（字幕組命名、資料夾名含「動漫」「番劇」「anime」等），先查 Bangumi，查不到再回退 TMDB。
  3. 豆瓣只補充中文簡介和評分，可在設定裡關閉（尚未實作）。
  4. NFO 暫不使用：讀 NFO 要逐個請求網盤，與「刮削不碰網盤」衝突。讀取程式碼保留，日後再接。
- **分類由刮削決定**（已確認，取代先前的「掛載目錄類型」）：掛載不設定類型。
  - 掃描只列目錄，按檔名和資料夾建立「待歸類」的暫定條目（猜測是電影還是劇集、標題、年份、季集），不放進任何媒體庫。
  - 刮削時依來源回傳的資料決定媒體庫，共五類：電影、電視劇、動漫、綜藝、紀錄片。
    - TMDB 類型含「動畫」→ 動漫（不限國家，所有動畫都算）；Bangumi 的結果一律是動漫。
    - 劇集類型含「真人秀」或「脫口秀」→ 綜藝。
    - 類型含「紀錄片」→ 紀錄片。
    - 其餘按電影 / 劇集分到電影或電視劇。
  - 按猜測的類別搜不到時，換另一類再搜（電影 ↔ 劇集）；只有單集的劇集才能轉成電影。
  - 都搜不到的留在「未匹配」，不出現在媒體庫、搜尋、最近新增、繼續觀看；可手動匹配，並可選擇電影 / 劇集和分類。
  - 刮削只請求 TMDB / Bangumi，不請求網盤。
  - 來源只說「電影」或「劇集」時，由標題資料夾**之上**的分類資料夾決定：含「綜藝 / 真人秀」→ 綜藝，含「紀錄」→ 紀錄片，含「動漫 / 動畫 / 國漫 / 番劇」等 → 動漫。來源給出明確類型（動畫、真人秀、紀錄片）時以來源為準。
  - 動畫資料夾裡的電影先查 TMDB 再查 Bangumi；劇集先查 Bangumi。
- **整理過的檔名**：`標題 (年份)/標題 (年份) - 1080p` 與 `標題 (年份)/Season N/標題 - S01E01 - 第 1 集` 這類 MoviePilot 式命名，標題原樣採用，不再拆解（例如「仙逆劇場版：弒仙之戰」「三國的星空第一部」）。
- **命名規則變更後重新歸檔**：啟動時若規則版本較新，直接用資料庫裡已有的路徑重新解析和歸檔，不列網盤目錄，然後刮削。
- **TMDB 位址錯誤**：搜尋回 404 時中止並提示檢查位址，不再把所有條目悄悄標成未匹配。設定頁有「測試連線」。
- **Quark 登入**：掃碼為主，手動貼 Cookie 為備用（Android TV 也能登入）。
- **Quark 掃描頻率**：列目錄請求必須限速（請求間隔、併發數、每日上限可設定），
  定時掃描的最小間隔要比其他驅動長，並優先用增量方式減少請求數。
- **TMDB 連線**：設定裡提供自訂 API 域名、代理、自備 API key。
- **掃描觸發**：手動、啟動時、定時，可按掛載點單獨設定。

## 4. 架構

```
┌──────────────── 現有 UI（首頁 / 媒體庫 / 詳情 / 播放器 / 下載）────────────────┐
│                         只依賴 MediaServerClient                             │
└───────────────────────────────┬──────────────────────────────────────────────┘
                                │
                     LocalLibraryClient（新）
                                │
        ┌───────────────────────┼───────────────────────┐
        │                       │                       │
   媒體庫資料庫            掃描器 / 刮削器          串流代理（127.0.0.1）
   （drift 新表）               │                       │
                                └───────────┬───────────┘
                                            │
                                    存儲驅動層（VFS）
                             ┌──────────────┼──────────────┐
                        本地      SMB      WebDAV      Quark
```

核心思路：把本地媒體庫寫成一個新的 `MediaServerClient` 實作，資料來自本地資料庫。
先加後刪——新後端跑通後再拆舊後端，過程中 app 一直可運行。

### 4.1 存儲驅動層

統一介面（參考 OpenList 的 driver 概念）：

| 能力 | 說明 |
| --- | --- |
| `list(path)` | 列目錄，回傳名稱、大小、修改時間、是否目錄、穩定 ID |
| `stat(path)` | 取單一檔案資訊 |
| `openRead(path, range)` | 範圍讀取，回傳位元組流 |
| `link(path)` | 可選：回傳直鏈（URL、必要標頭、過期時間） |
| 寫入類 | 首版不做（重新命名、刪除、上傳） |

- 每個掛載點一筆設定：驅動類型、顯示名稱、根路徑、憑證引用。
- 憑證（Cookie、SMB 密碼）存入現有的 `credential_vault`，設定匯出時不得明文帶出。
- **本地驅動**：桌面直接走檔案系統；Android 走 SAF（專案已有 `saf_util` / `saf_stream`）。
- **SMB 驅動**：Dart 無成熟的 SMB2/3 庫，預計以 FFI 接 libsmb2，為四個首版平台各自編譯。
  動手前先做可行性驗證（見第 7 節）。
- **WebDAV 驅動**：標準 PROPFIND 列目錄、帶 Range 的 GET 讀取，支援 Basic / Digest 認證和自簽憑證選項。
  可直接掛現有的 OpenList / AList、NAS、堅果雲等。
- **Quark 驅動**：Cookie 認證；直鏈需要 Cookie 與特定 User-Agent，會過期；要做請求限速。
  流程已由專案擁有者參照 OpenList 實測可行。

### 4.2 串流代理

app 內起一個只綁定 127.0.0.1 的 HTTP 服務，所有播放和下載都經過它：

- 支援 Range 請求。
- 為上游請求注入 Cookie / User-Agent。
- 直鏈過期時自動重新取鏈，對播放器透明。
- 把 SMB 的範圍讀取轉成 HTTP。
- URL 帶隨機 token，避免本機其他程式存取。

好處是 mpv、ExoPlayer、外部播放器、下載器都只需要認識普通 HTTP。

### 4.3 媒體庫資料庫

已實作（schema v27，`lib/database/library_tables.dart`；查詢層在 `lib/library/library_repository.dart`）：

| 資料表 | 內容 |
| --- | --- |
| `library_items` | 電影、劇集、季、集共用一張表；含標題、排序標題、別名、年份、簡介、評分、季集編號、圖片來源、各刮削源的外部 ID、手動鎖定旗標 |
| `library_files` | 掃到的檔案：影片、字幕、圖片、NFO。同一條目的多個影片就是多個版本；含檔名解析結果、匹配狀態、懶加載的媒體資訊、最後一次見到它的掃描編號 |
| `library_user_states` | 播放進度、已看、播放次數、收藏、從「繼續觀看」隱藏 |
| `library_genres`、`library_item_genres` | 類型 |
| `library_people`、`library_credits` | 演職員 |
| `library_lists`、`library_list_items` | 合集與播放列表，共用結構，以 `kind` 區分 |
| `library_scan_states` | 每個掛載點的掃描進度，供中斷後續掃 |

與原草案的差異：

- **搜尋用 `LIKE` 而不是 FTS5。** FTS5 的預設分詞器不切分中文，trigram 分詞器又搜不到兩個字的片名（例如「三體」）。
  個人片庫的規模下 `LIKE` 足夠快，而且任意長度的中文都能搜。標題、原始標題、別名三欄都會比對。
- **圖片來源直接存在條目上**（海報、背景、標誌三欄），沒有獨立的 `artwork` 表。
- **合集和播放列表合併成一組表。**
- 現有的 `ApiCache`、`Connections`、`Profiles` 等舊表仍留著，到階段 6 才移除。

### 4.4 掃描器

已實作（`lib/library/`：`media_name_parser.dart`、`media_classifier.dart`、`library_scanner.dart`、`library_scan_service.dart`）：

- **增量**：路徑相同的檔案保留原有資料列、匹配和媒體資訊；大小或修改時間變了才清掉媒體資訊。
- **可續掃**：待訪問的目錄佇列在每個目錄處理完後寫回資料庫。取消或失敗後再掃，會沿用同一個掃描編號從中斷處繼續。
- **不誤刪**：只有完整跑完的掃描才會移除「這次沒見到」的檔案；中途失敗不刪任何東西。
- **檔名解析**：年份、季集編號（`S01E02`、`1x02`、`第2集`、中文數字、全形數字）、字幕組方括號、
  絕對集數、OVA/SP、解析度、來源、編碼、HDR、版本標記、發佈組。
- **初步猜測**：有明確集數標記的是劇集；單純的數字只有在季資料夾內、字幕組命名、或同目錄有三個以上帶編號的影片時才當作集數；其餘當電影。這只是刮削時的搜尋依據。
- **建立條目**：掃描時按解析出的名稱建立暫定條目（電影，或劇集、季、集），狀態為「待歸類」，刮削後才進入媒體庫。
  同名同年的檔案歸到同一條目，形成多版本。已歸類劇集的新集數直接跟隨該劇所在的媒體庫。
- **重新歸檔**：檔案改名或移動後，未被手動鎖定的影片會重新歸檔；舊條目若因此變空會被清除。
- **字幕**：依檔名前綴關聯到影片，並從後綴識別語言（`chs`、`cht`、`zh-TW`、`en` 等）。
- **略過**：樣片、預告、花絮目錄、`BDMV` 等光碟結構、隱藏目錄與系統目錄。

尚未做：啟動時與定時自動掃描（目前是手動和儲存掛載後自動掃一次）；一檔多集只歸到第一集；
多碟（cd1/cd2）不會合併。

### 4.5 刮削器

已實作（`lib/library/scrapers/`、`library_scraper.dart`、`library_scrape_runner.dart`、`library_settings.dart`）：

- **來源**：TMDB、Bangumi。看起來像動漫的先查 Bangumi 再查 TMDB。同目錄的 poster、fanart 從資料庫已有的檔案清單找出，顯示時才經代理讀取。
- **歸類**：見第 1 節「分類由刮削決定」。schema v29 升級時把未手動鎖定的條目重設為待歸類並重新刮削，不需重掃網盤。
- **匹配**：名稱相似度加年份校驗，低於門檻不採用，留在未匹配。帶年份查不到會去掉年份再查一次。
- **合併**：兩個檔名刮到同一個外部 ID 時合併成一個條目，原檔名寫入別名，之後重掃會歸到同一條目。
- **劇集**：只抓片庫裡實際有檔案的季，補上各集標題、簡介、劇照。
- **手動匹配**：可搜尋並指定條目；手動結果會鎖定，重掃和自動刮削都不覆蓋。
- **設定**（schema v28 的 `library_settings` 表）：TMDB key（加密存放）、語言、API 與圖片位址、HTTP 代理、是否啟用 Bangumi。
- **沒有 key 時**：需要 TMDB 的條目留在佇列而不是被標成未匹配，設定 key 後會自動重試。

尚未做：**豆瓣**（沒有公開 API，尚未實作）；完全無法從檔名識別的檔案（沒有條目）還不能手動指定。

### 4.6 本地後端

已實作（`lib/library/local_library_client.dart`）：`LocalLibraryClient implements MediaServerClient`，
以本地資料庫回答原有介面的查詢，並註冊成一台永遠在線的「伺服器」。

- 條目沿用中性的 MediaBrowser 條目形狀（`MediaItem.jellyfin`），避免改動介面裡所有的條目分支。
- 媒體庫固定三個：電影、電視劇、動漫；沒有內容的不顯示。
- 播放、外部播放器、下載都經串流代理取得網址；外掛字幕以側載方式提供。
- 進度回報直接寫本地資料庫，達到 90% 視為看完。
- 啟動時自動建立一個本地 profile，不再導向登入頁；沒有任何掛載時直接打開掛載頁面。
- 設定頁新增「媒體來源」分組；伺服器連線與第三方服務的入口只在仍有伺服器連線時顯示。

尚未做：篩選器面板（類型、年份等篩選邏輯已支援，但沒有提供給介面的篩選器清單）；音軌與內嵌字幕資訊（由播放器自行從檔案讀取）；
片頭片尾標記、進度條預覽縮圖、檔案資訊頁。

## 5. 階段

每個階段結束時 app 都應可建置、可運行。

### 階段 1：存儲驅動層與串流代理

- 驅動介面、掛載點設定與憑證存放。
- 本地、SMB、WebDAV、Quark 四個驅動。建議順序：本地 → WebDAV → Quark → SMB，
  先用簡單的驅動把介面和代理跑通，SMB 的原生庫風險最後處理。
- 迴環串流代理。
- 一個除錯用的檔案瀏覽頁面。

**完成標準**：在除錯頁面瀏覽四種掛載點，選一個遠端影片能直接播放並拖動進度；
Quark 直鏈過期後播放不中斷。

### 階段 2：媒體庫資料庫

- 新表與遷移（schema v26 起）。
- 查詢層：分頁、篩選、排序、搜尋。

**完成標準**：用測試資料灌庫後，各查詢的單元測試通過。

### 階段 3：掃描器與自動分類

- 增量掃描、檔名解析、分類規則、多版本合併、字幕關聯、限速。
- 建立檔名解析的測試語料（中文命名、動漫、多版本）。

**完成標準**：對一個真實掛載點掃描，結果寫入 `scan_entries` 並產生待刮削條目；
重複掃描不產生重複資料；中斷後可續掃。

### 階段 4：刮削器

- 四個來源、匹配與信心度、圖片快取。
- 「未匹配」分類與手動匹配介面。

**完成標準**：掃描後的條目自動帶上標題、簡介、海報；匹配失敗的出現在未匹配分類，
手動匹配後正確入庫。

### 階段 5：本地後端接入

- 實作 `LocalLibraryClient`。
- 掛載管理介面取代伺服器登入流程。
- 下載改為經串流代理從驅動下載。

## 7. 風險與待驗證

| 項目 | 風險 | 處理 |
| --- | --- | --- |
| SMB | 已用 `dart_smb2`（基於 libsmb2）接入，Windows 可建置；尚未連過真實共享，Android、macOS、Linux 建置未驗證；不支援自訂連接埠 | 用真實 NAS 驗證播放與拖動；不行再試 `smb_connect` |
| Quark | 非官方 API，介面可能變動；掃描目錄過於頻繁會觸發風控 | 流程已實測可行；驅動內集中處理限速與重試，掃描頻率可設定且預設保守 |
| 自動分類 | 檔名把電影誤判為劇集（或相反），或 TMDB 類型標得不準 | 搜不到時自動換類別再搜；手動匹配可改電影 / 劇集與分類，結果鎖定 |
| 豆瓣 | 無公開 API，非官方介面隨時失效 | 只作補充源，可關閉，失敗不影響入庫 |
| TMDB | 部分網路環境連不上 | 自訂域名與代理 |
| 無轉碼 | 高碼率影片在弱設備或慢網路上無法降級 | 後續接 Quark 轉碼流 |
| 多設備 | 每台設備各自掃描刮削，進度不互通 | 首版提供匯出匯入；同步排到後續 |
| 大庫效能 | 網盤首次掃描和刮削耗時長 | 增量、可續掃、背景執行、先顯示已完成部分 |
| 媒體資訊 | 伺服器不再提供編碼、音軌資訊 | 懶加載探測；未探測時介面隱藏相關標記 |
| 上游修復 | 分家後無法合併上游更新 | 播放器、焦點導航等修復手動挑選移植 |
| 授權 | OpenList 為 AGPL-3.0 | 只參考思路，不複製程式碼 |
| 測試 | 大量現有測試隨舊後端刪除 | 掃描、解析、刮削、查詢層新建測試 |

### SMB 套件調查（2026-11-09，僅查閱 pub.dev，未實測）

| 套件 | 實作 | 協議 | 平台 | 狀態 |
| --- | --- | --- | --- | --- |
| `dart_smb2` 0.3.0 | 基於 libsmb2（原生庫） | SMB2/3 | macOS、Windows、Linux、iOS、Android | 活躍，兩天前剛發佈；BSD-3-Clause |
| `smb_connect` 0.0.9 | 純 Dart | SMB1、2.0、2.1，無 3.x | Android、iOS、Linux、macOS、Windows | 21 個月未更新；Apache-2.0 |

已確認：`dart_smb2` 提供任意偏移的範圍讀取（`readFileRange`），原生庫由建置鉤子下載預編譯檔並核對 SHA-256，
以動態庫形式打包（libsmb2 為 LGPL-2.1，內含 OpenSSL libcrypto）。
待驗證：Android TV、macOS、Linux 上的建置，以及真實共享上的播放。
