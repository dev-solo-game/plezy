# 媒体库服务器同步与设备遥控设计

**状态**　设计评审稿，2026-11-18。文中的按钮、提示和验收结果描述目标体验。第一期交付本地使用、账号同步和局域网遥控；第二期增加异地遥控。下文单列代码现状，便于区分已有能力和待实现行为。

**适用范围**　Plezy 自建媒体库、同步账号和设备遥控。此前方案中关于局域网互传片库、双通道同步和投播前自动拉取其他设备片库的设想，由本文取代。Plex、Jellyfin 等既有媒体服务继续按各自的连接方式工作。

## 1. 用户最终得到什么

用户可以直接打开应用，添加 NAS、网盘或本机目录，在一台设备上建库、观看和记录进度。想让电视与手机共享片库时，在两台设备登录同一个同步服务器账号。想把手机当电视遥控器时，只需电视开启遥控接收，并完成相应授权。两种需求可以分别满足。

| 用户所处环境 | 片库、收藏、续播进度 | 手机上能做什么 |
|---|---|---|
| 仅使用本机 | 数据保存在本机，重开应用可继续使用 | 浏览、播放、扫描、改匹配 |
| 两台设备同一 Wi-Fi，均未登录 | 两边维护各自的片库 | 配对后，可控制电视正在播放的内容，也可指定电视能访问的影片 |
| 两台设备同一 Wi-Fi，登录同一同步账号 | 通过同步服交换已提交的变化 | 优先局域网直连；电视开启接收后，同账号设备可直接连接 |
| 已登录，家里外网中断，但路由器和 NAS 正常 | 本机继续工作，修改等待上传 | 已有有效授权的手机继续通过局域网控制电视 |
| 两台设备异地，登录同一账号，均能访问同步服 | 设备分别上线即可同步，双方不必同时在线 | 第二期支持通过服务器控制在线设备；遥控需要双方同时在线 |

**一次家庭使用的例子。** 手机把电视拖到第 18 分钟，电视确认后，手机遥控页显示 18:00。电视继续播到 23:10，退出播放器时保存自己的观看记录。手机下次打开片库，在账号同步后看到“继续观看 23:10”。如果电视此时断网，手机片库暂时显示上一次已同步的位置，遥控页仍可显示电视的实时位置。用户能从页面标题“正在控制客厅电视”和“我的片库”辨认这两个数字的来源。

**一次外出与回家接力的例子。** 用户通勤时用手机移动网络看网盘版第 3 集到 32:15，直接锁屏或切到后台；应用在暂停与切后台时保存进度并触发上传。回家唤醒待机中的客厅电视，电视回到前台时自动向同步服拉取增量，首页“继续观看”更新为第 3 集 32:15；点击后优先使用当前可达的家庭 NAS 高码率版本从 32:15 续播，无需先掏出手机解锁打开应用。

**同步服务器的部署位置与服务形态。** 同步服基于 SQLite WAL 持久化，只保存结构化元数据、观看状态和端到端加密（E2EE）封装的共享源凭据，不存储或中转音视频流。它既支持作为**公共多租户服务器**（支持网页注册、用户面板管理设备与改密、以及管理员面板控制注册开关与用户配额），也可在家庭内网 NAS（如 Docker）单二进制自托管；客户端默认服务器地址预填 `http://127.0.0.1:8088` 便于调试与本地部署。即便内网自建无公网 IP，手机在外产生的进度也会先写入本机待上传队列，回家连上 Wi-Fi 后自动补传至同步服，仍不需要手机与电视同时亮屏在线。

## 2. 用户怎么操作

### 2.1 首次打开与添加媒体源

| 步骤 | 用户操作 | 应用反馈与结果 |
|---|---|---|
| 1 | 首屏选择「直接使用」或「登录同步服务器」 | 「直接使用」的说明为“片库保存在本机，稍后可登录以跨设备同步”。用户可以直接进入主页。 |
| 2 | 在「媒体源」添加 NAS、网盘或本机目录，选择扫描范围 | 显示源名称、连接状态和扫描入口。用户能看到当前扫描的源以及陆续发现的影片。 |
| 3 | 在手机本地收藏一部电影，稍后打开电视 | 未登录时，电视继续显示自己的片库。手机可在「设置 → 片库同步」查看如何启用跨设备同步。 |

首页不需要让用户理解 P2P、对端游标或连接拓扑。设置中保留两个入口：「片库同步」管理账号和上传状态，「遥控设备」管理设备发现、接收与授权。

### 2.2 家里没有同步服务器，用手机遥控电视

1. 在电视「设置 → 遥控设备」确认开启「允许此设备被遥控」（电视与桌面端默认开启，手机端默认关闭），确认易认的设备名，如“客厅电视”。
2. 手机连接同一局域网，打开「遥控设备」，点“客厅电视 → 配对”。电视显示请求方名称与校验信息，用户核对后确认。之后在有效配对下可直接连接。仅发现局域网设备时不会自动弹窗打扰，只在控制端主动发起配对时目标端弹出授权确认。
3. 手机显示“正在控制客厅电视 · 局域网”。电视正在播放时，显示片名、播放状态和当前位置；电视空闲时显示“设备已连接，当前未播放”。暂停、快进和拖动后的结果以电视回传状态为准。
4. 在手机点「断开」只结束本次遥控，电视继续播放。在电视点「撤销配对」则断开依赖该配对的现有控制会话，之后须重新授权。关闭电视的遥控接收会结束所有入站控制。

配对提示应写“允许这台手机控制播放”。配对不复制媒体源凭据、片单、收藏或历史进度。设备发现只提供候选目标，可执行命令的权限来自有效授权。

### 2.3 手机指定“在客厅电视播放”

这个入口与控制电视现有播放分开处理。用户可以遥控一部只存在于电视片库的影片；反过来，手机能播放的文件，电视还需要有可用的播放来源。

| 情况 | 操作后的体验 |
|---|---|
| 手机与电视均可访问同一文件 | 在影片详情点「在设备上播放 → 客厅电视」。电视优先打开对应文件版本，实际起播后手机进入遥控页。 |
| 两端都有同一作品，但文件版本不同 | 根据作品和集号定位电视上的可用版本。若使用其他版本，在遥控页显示电视实际播放的版本。 |
| 双方连接同一 Plex 或 Jellyfin 媒体服务 | 使用已有媒体服务器和条目标识，在电视自己的连接上解析目标。 |
| 电视已登录同一同步账号，索引暂时落后 | 电视先查本机，未命中时从账号同步服刷新一次再查。手机显示“正在客厅电视上查找影片”。 |
| 电视没有该片，或视频只存在于手机私有目录 | 提示“客厅电视找不到这部影片，可在电视添加媒体源，或在手机播放”。电视当前播放应继续。 |
| 电视有索引，但 NAS 离线或授权失效 | 提示“客厅电视暂时无法访问媒体源”，保留条目。恢复连接或重新授权后可重试。 |

第一期沿用接收端直接访问媒体源的方式。启动播放请求只需要目标标识、版本、集号和起播位置等必要信息。视频代理、手机文件传输属于单独的媒体传输能力。

### 2.4 已有本地片库，后来登录账号

在「设置 → 片库同步」输入服务器地址并登录。电视可用已有的二维码登录流程。手机与电视应绑定同一服务器上的同一账号；相同用户名出现在两台独立服务器时，视为两个账号。

| 首次绑定时的情况 | 建议交互 | 完成条件 |
|---|---|---|
| 空设备登录已有账号 | 显示“正在恢复片库”，已恢复的内容可逐步浏览 | 同步完成后可看到共享索引、收藏与观看记录；进入播放时再验证目标源是否可达 |
| 有本地库，注册自己的空账号 | 提示“将本机可共享的媒体源、片库与观看记录同步到此账号”，确认一次 | 本机内容继续可用；另一台新设备登录后能恢复 |
| 本地库和账号库都有内容 | 提供「合并本机片库」和「仅使用账号片库」。前者列明导入范围；后者保留原本地库，独立存放 | 同源、同作品按稳定标识去重；本地独有修改得到保留。确认过的选择在同账号重登时复用 |
| 账号 A 改为账号 B | 进入 B 的片库，A 的待上传内容仍归 A。退回本地使用显示对应本地库 | 切回 A 后继续 A 的上传。晚到的 A 请求也只能更新 A |

**首次同步的反馈。** 验证凭据成功后可以显示“已登录”。首次导入尚未完成时，继续显示“正在合并片库”或“已暂停，联网后继续”。只有已处理完本轮拉取和待上传修改时，才显示“已同步”和最近完成时间。期间照常保存新产生的观看进度。私有磁盘路径、设备专属访问状态留在本机；有稳定作品标识的观看记录可以跨设备使用。

**本地库与多账号存储隔离。** 应用级配置（Plex/Jellyfin 连接、Profile、离线下载任务及本机遥控配对）保存在宿主主库中持久保留；自建片库的媒体源、索引、片单/合集、观看状态、同步日志、刮削配置与待上传队列按「本地工作区」与「账号工作区（`serverUrl + userId`）」归档隔离，切换工作区前先停止后台扫描与同步任务再整体切换，确保各账号及本地库之间互不串库，且不影响既有媒体服务器连接。

### 2.5 断网、退出账号与异地遥控

| 用户遇到的事 | 用户看到什么 | 恢复方式 |
|---|---|---|
| 同步服不可达 | 片库仍可打开；设置显示“等待联网，修改已保存在本机”。同 LAN 的已授权遥控仍可连接 | 恢复后自动补传；「立即同步」可手动重试 |
| 退出同步账号 | 提示有无待上传修改，保留该账号的本机数据与队列。账号授予的遥控权限随退出失效 | 登录原账号继续同步。另行建立且未撤销的本地配对仍可用于本地遥控 |
| 电视离线或退出遥控接收 | 显示“设备离线”或“设备未开启遥控”。若命令已发出但未收到回执，显示“未确认” | 重新连接后读取电视实际状态，再由用户决定是否再次操作 |
| 手机从家中 Wi-Fi 切到移动网络 | 第一期提示局域网连接已断开。第二期在同账号、双方在线时可重新连接到“客厅电视 · 服务器” | 重新获取会话状态，已过期的暂停、快进或播放命令不补发 |

## 3. 持久化数据、实时控制与视频各走哪条路径

| 对象 | 谁产生、谁保存 | 路径和时效 |
|---|---|---|
| 媒体源、作品匹配、文件索引、删除记录、刮削配置 | 客户端在扫描或用户确认后写本地；同步服保存账号范围内的状态 | 客户端经账号 push/pull 增量同步，支持离线补传。采用精简卡片骨架（外部 ID、标题、年份、评分、海报路径、分类），剔除演职员表与分集长简介以大幅压缩同步体积；详情页按外部 ID 自动补拉并缓存在本地。共享源凭据与 TMDB API Key 均经 E2EE 加密封装同步 |
| 收藏、播放列表与合集、片头片尾偏好、观看记录 | 执行相应操作的设备写入；播放中的观看记录由实际播放端写入 | 随账号数据增量同步（含自定义播放列表与合集 `sync_lists`）；本机离线缓存或私有目录视频若具备稳定作品标识（`work_key`），其观看记录与整剧偏好同样随账号同步。用户主动倒回重看时，以新的观看操作为准 |
| 遥控命令和实时播放状态 | 控制端发送命令，播放端执行、确认并回传状态 | 同 LAN 优先走已授权直连，第二期可由账号服务器转发。命令只对当前在线会话有效 |
| 视频、音频、字幕文件 | 已配置的 NAS、网盘、媒体服务或接收端本地存储提供 | 播放端从其可访问的来源读取。片库同步传递定位信息，不复制视频内容；同一作品存在多来源版本时，续播按本机可用文件 > 可达局域网源 > 备用公网地址 > 网盘源自动择优 |

第二期可在同一个 `sync_server` 进程复用账号登录与设备身份，增加在线设备登记、状态查询和按目标设备转发。每台目标设备汇总为一行，LAN 和服务器同时可用时只建立一条活动控制路径。一次点击产生一个请求标识；连接切换后先读取状态，避免重复执行“快进 30 秒”。发送失败的实时指令不进入媒体库待上传队列。现有 `server/` 还承担房间中继等职责，账号遥控的权限以 `sync_server/` 的账号会话为准。

**续播时机与前台唤醒同步。** 播放端在播放中定期落盘本机进度，并在暂停、拖动稳定后、切集或播完、应用切入后台/锁屏及长时播放检查点（如每 90 秒）写入待上传队列并立即触发异步推送；若当前已有同步任务在运行，记录补推标记并在本轮结束后立即补推，避免切后台前的进度被静默跳过。电视或手机从待机唤醒、切回前台（`resumed`，带节流冷却）时，自动执行一次增量拉取并复探存储源可达性，局部刷新“继续观看”列表；若户外启动首秒探活未完成导致首选内网源不可达，播放器可回退尝试同集其他可用来源版本。

## 4. 扫描与服务器同步的并发约定

这里的“增量扫描”是客户端询问存储源有哪些文件变化；“增量同步”是客户端向账号服务器交换已提交的数据库记录。一个网盘列目录耗时几分钟，依然可以及时上报播放进度。

| 正在做什么 | 此时发生什么 | 应有结果 |
|---|---|---|
| 同一源正在全盘扫描 | 账号同步或电视上报进度 | 进度正常同步；可发布已提交的新增和更新。扫描成功覆盖相应范围后，才提交依据缺失推导的删除 |
| 同一源正在全扫 | 用户点增量、再次点全扫，或打开剧集详情 | 重复全扫显示已有任务；增量请求合并延后。详情先显示已有条目，确有需要时全扫结束后补查该目录 |
| 正在增量扫描 | 用户明确要求全扫 | 在安全边界结束或回滚本轮增量，再启动全扫；未提交的扫描水位不前移 |
| 新电视首次恢复，源信息已到，文件页还没收齐 | 用户点扫描 | 显示“待此媒体源恢复后扫描”。完成该源索引后再使用对应水位，避免恢复一半就发起全盘重扫 |
| 正在扫 NAS A | 网盘 B 有变更或收到遥控请求 | 允许 B 在资源配额内独立处理；遥控照常响应。取消 A 只影响 A |
| 扫描到一半断网、权限失效或用户取消 | 本轮尚有目录未访问 | 保留已有索引，标明“已中断”及原因。只恢复可验证的检查点；需要重扫时显示“重新扫描” |
| 同账号两台设备在线扫描同一网盘 | 后台自动扫描争用 | 复用服务端按源的扫描租约，后台任务只处理自己获得租约的源。用户主动核对时说明已有扫描状态 |
| 扫描期间收到更晚的文件记录或源配置变更 | 本地扫描准备收尾 | 保护本轮开始后写入的有效变更，必要时复核该目录。源删除或根目录变更按版本生效，旧任务停止向旧范围提交 |

删除、版本合并和游标属于服务器同步仍需保证的正确性。服务端确认某次上传，只能清除它已接受的操作；拉取页落库后才能推进该账号的拉取游标。重建中断后要能继续或安全重来；保留恢复期间产生的本地修改。播放进度时间相同且值不同时，客户端与服务端使用同一个稳定裁决规则，并用不同到达顺序验证结果。

## 5. 代码现状与实施顺序

| 范围 | 当前依据 | 变更与交付 |
|---|---|---|
| 一期 · 设备发现与授权 | 遥控会从 LAN 同步服务读取本机身份、已配对设备、共享密钥与遥控端口。[遥控 Provider](../lib/providers/companion_remote_provider.dart) | 提取遥控需要的发现、身份和信任存储，复用用户已有配对；解除现有“已登录同步服则屏蔽本地配对上下文”的互斥限制，使账号授权与本地配对独立并存。保留现有遥控协议、播放器接收端及既有媒体账号鉴权 |
| 一期 · 退役片库 P2P | LAN 服务同时承担配对、变更通知、分页拉取、推送和快照。部分配对完成回调会自动启动同步。[LAN 服务](../lib/library/sync/lan_peer_sync_service.dart) | 关闭所有 LAN 片库读写接口、通知、定时触发及配对后同步。设置页移除“同步所有局域网设备”，旧客户端请求也无法读写新版片库 |
| 一期 · 投播与界面 | 解析目标失败后，未登录设备会尝试同步所有可信设备；首屏和设置也依赖旧模式。[播放启动](../lib/services/companion_remote/remote_playback_launcher.dart) · [首屏](../lib/screens/auth_screen.dart) | 改成第 2 节的查找与失败反馈。电视扫码登录的设备名称从通用设备身份读取，避免依赖被移除的同步服务 |
| 一期 · 账号片库 | 云端流程已有离线队列、日志、增量游标、源去重和扫描租约。[同步协调器](../lib/library/sync/sync_coordinator.dart) · [服务端路由](../sync_server/handler.go) | 保留共享日志、映射器、加密和账号 API；后端升级为 SQLite 持久化与 Web 用户/管理双面板；增量同步新增 `sync_lists` 片单/合集与加密刮削配置，作品元数据采用精简骨架 + 详情页按外部 ID 懒补全；本地库与各账号工作区通过归档切换隔离，保持宿主库中的 Plex/Jellyfin、下载与设备配对不受切账号影响。将“已登录”与“首次同步完成”分别持久化；向增量扫描显式传入实际获批租约的源集合 |
| 一期 · 续播时机与选源 | 唤醒回前台未触发自建库增量拉取；推送遇并发同步时直接返回；未探活内网源默认按在线排序。[应用入口](../lib/main.dart) · [播放上报](../lib/library/local_library_client.dart) · [挂载探活](../lib/storage/mount_manager.dart) | 前台 `resumed` 增加带冷却的增量拉取与可达性复探；`SyncAndScanCoordinator` 增加补推锁存与切后台/锁屏前即时落盘冲刷；播放启动遇到未探活离线内网源时支持自动回退同集可用版本，并在拉取新增挂载后及时刷新挂载缓存 |

### 升级时怎样处理老用户

1. **原来使用局域网同步。** 升级后进入本地片库，原有媒体源、索引、观看记录与遥控配对保留。一次性说明“局域网设备仍可遥控。今后要共享片库，请在各设备登录同一同步账号。”用户主动绑定前，各设备继续独立保存。两台设备各自独有的记录，在各自完成账号导入后才能汇合。
2. **原来已登录同步服。** 保留现有会话和与该账号可确认关联的数据。升级不应无故重新建库或上传一遍整个片库。归属无法确定的旧待发送记录留在本机，进入首次绑定流程后再处理。
3. **新旧客户端混用。** 新版保留兼容的遥控授权和命令，关闭片库接口。旧机上的“局域网同步”可能显示不可用。两台旧机仍可能按旧协议互传，因此家庭设备全部升级后，整个家庭才完全退出 P2P 片库同步。
4. **删除旧状态。** 升级先完成身份与配对迁移，再退役仅用于对端同步的游标、确认序号和重建上下文。使用旧数据库样本验证迁移可重复执行、进程中断可重试。同步服也使用的日志、稳定标识与本地业务数据应保留。

## 6. 发布验收

使用手机 A、电视 B、电脑 C、一个共享 NAS 和一个可断网的测试同步服。先在旧版分别准备独有影片、同一作品的不同进度和已有遥控配对。检查界面反馈、两端持久化数据及真实网络请求；仅看到两端海报数量相同，无法证明通道或归属正确。

| 阶段 | 操作 | 通过条件 |
|---|---|---|
| 一期 | A、B 未登录，配对并遥控；A 新增片源、收藏和进度 | B 能暂停、快进并回传状态；B 的持久化片库没有收到这些修改，双方没有片库 LAN 拉取或推送 |
| 一期 | 旧版 C 主动向新版 A 请求快照、推送修改 | 请求无法读取或修改 A 的片库；新版的本地遥控仍可使用 |
| 一期 | A 让 B 播放已有影片，再播放仅存在于 A 私有路径的影片 | 首次成功；第二次明确告知找不到或不可达，B 原有播放不受影响，A 的私有路径或凭据不会被导入 B |
| 一期 | A 将已有库绑定空账号，B 扫码登录；随后两端错时上线 | B 恢复共享索引和进度；两端独有记录在导入后汇合，相同源、作品不重复 |
| 一期 | 首次拉取半途关闭 App；服务端接受上传后丢弃响应；恢复期间再看一集 | 能恢复或重试，同一操作只生效一次，新进度仍在；本轮完成前界面不显示“已同步” |
| 一期 | A 的待上传队列非空时退出并切到另一个账号 | 新账号看不到旧账号片库、凭据和队列。切回原账号后可继续上传 |
| 一期 | B 全扫到一半关闭 NAS；同时 A 重看同一集、回退进度 | 未扫描目录不会被标为删除，较新的回看操作可同步；恢复后可继续或明确重扫 |
| 一期 | 断开同步服，A 通过 LAN 控制 B 到 18:00，B 播到 23:10 退出 | 电视保存 23:10，手机遥控界面反映电视状态。恢复后手机片库得到 23:10，没有重复观看记录 |
| 一期 | A 在移动网络看网盘版第 3 集至 32:15 后直接锁屏切后台；随后唤醒待机中的电视 B（同剧同时有内网 NAS 版与网盘版） | A 切后台时完成入队与上传；B 唤醒回到前台后自动拉取并显示 32:15，点击继续观看优先起播内网 NAS 版本，全程无需解锁打开 A |
| 一期 | 撤销本地配对、关闭接收、退出账号，分别验证授权 | 依赖已撤销授权的会话结束。关闭接收后所有控制来源失效；账号退出后只有独立有效的本地配对可重新授权 |
| 二期 | A 切到移动网络控制同账号 B，再让 B 离线并重连 | 在线时命令有回执；重复请求不重复执行。离线命令不会在 B 重连后补执行；其他账号无法控制 B |

一期可独立发布。对外说明应明确“未登录可本地使用和局域网遥控；跨设备片库共享需登录同步服务器”。待第二期异地控制通过在线路由、权限与断线验收后，再对外提供“跨网络遥控”。
